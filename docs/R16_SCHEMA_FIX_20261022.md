# R16 修复规划：工具 function schema 缺顶层 type:object 导致对话内注册失败

> 创建：2026-10-22
> 任务：#50
> 范围：仅前端工具 schema 结构 + 离线契约校验；不改后端业务逻辑，不重打 onedir runtime。

## 1. 现象

对话内模型工具注册/调用阶段报错：

```
Invalid schema for function 'create_postprocess_task':
schema must be a JSON Schema of 'type: "object"', got 'type: null'.
(request_id: cc9541df-625a-4e11-9154-b82789fee997)
```

离线契约自测 18/18 PASS，但对话内被模型网关/SDK 拒绝。

## 2. 根因（已用源码 + 离线实跑证据确认）

### 2.1 致命项：parameters 是扁平表，缺 object 根

自研 `defineTool()`（`src/index.js:448-472`）直接透传：

```js
parameters: options.parameters ?? {},
```

作者侧参数表写法是扁平结构：

```js
parameters: {
  kind: { type: "string", description: "...", required: true },
  orbitals: { type: "array", items: { type: "integer" } },
}
```

而发给模型的 function schema 必须是标准根对象：

```js
parameters: {
  type: "object",
  properties: { kind: { type: "string", ... }, orbitals: { type: "array", items: { type: "integer" } } },
  required: ["kind"],
}
```

网关读取 `parameters.type`，扁平表顶层没有 `type` 字段，解析为 `null`，于是报
`must be a JSON Schema of 'type: "object"', got 'type: null'`。报错点名 `create_postprocess_task`
只是日志遍历到的代表；离线实跑（`docs/_verify/schema_inspect.mjs`）证实 **18/18 工具全部中招**：
`parameters.type = undefined`，均为扁平表。

### 2.2 对照官方范本

- dsh-tools 官方 `defineTool`（解包副本 `docs/_dsh_unpack/.../lib/types/schema.js:274-304`）：
  - `parameters = parameterSchemaSpecToJsonSchema(options.parameters)` → 编译成 `{type:"object", properties, required?}`（schema.js:238-247）；
  - `outputSchema = valueSchemaSpecToJsonSchema(options.output.schema)` 编译输出 schema。
- 本机正常范本 `@aifs/dsh-plugin-aifs`（`lib/index.js:2121-2140`）内联复用同一套编译函数，参数表同样先编译为 object root。
- 旧离线脚本 `output_contract_check.mjs` 只对 `output.schema` 跑子集白名单校验，**从未校验 parameters 顶层结构**，所以扁平表被漏网放行。

### 2.3 次要项：output.schema 缺省为空对象

工厂兜底 `schema: userOutput.schema ?? {}`。空 `{}` 在 DSH `assertSupportedJsonSchema` 里属于
合法的 annotation-only（无 type、无约束关键字，json-schema.js:223-228 放行），不会在 register 阶段抛错；
但范本缺省用官方 `{type:"json"}` 语义（annotation-only 任意 JSON）。为对齐范本、消除后续结构化输出/
SDK 投影歧义，本轮统一把未声明 output 的工具编译为 annotation-only 任意 JSON 节点。

### 2.4 报错出处边界

报错文案 `Invalid schema for function ... must be a JSON Schema of 'type: "object"'` 在本地
`E:\DSH\resources\app.asar` 内全量检索未命中，属模型提供商 / 网关 / SDK 的 function tools 校验层；
本地修复点仍是把 parameters 编译成合规 object root，使上游不再被拒。

## 3. 修复方案（最小改动，对齐官方语义，不引入运行时依赖）

build.mjs 已把 `@deepseek-ai/*` 列为 external，第三方插件运行时不保证能解析该作用域包；
因此在 `src/index.js` 内复刻官方两个编译函数的最小子集，不新增 import、不改 execute 行为。

### 3.1 新增编译函数（置于 defineTool 之前）

- `compileParameterSchema(spec)`：
  - 收集 `properties` 与 `required`（仅 `required === true` 入 required）；
  - 保留 `type / description / default / enum`；`array` 保留 `items`（递归 `compileValueNode`）；
  - 返回 `{ type:"object", properties, ...(required.length ? { required } : {}) }`；空表返回 `{ type:"object", properties:{} }`。
- `compileValueNode(def)`：编译单个值节点（参数 items、显式输出 schema 用），保留 `type/description/default/enum/items`。
- `compileOutputSchema(spec)`：
  - 未声明（undefined/null/非对象）→ annotation-only 任意 JSON（返回 `{}`，可带 description 注解）；
  - `spec.type === "json"` → 剥掉 `json` 标记，只保留注解（对齐官方 `type:"json"` 产物）；
  - 其他显式 schema 走 `compileValueNode`。

### 3.2 defineTool 改造

```js
const parameters = compileParameterSchema(options.parameters);
const outputSchema = compileOutputSchema(userOutput.schema);
const output = { schema: outputSchema, render: ..., ...presentationMeta? };
return { name, description, parameters, output, timeoutMs, execute };
```

- 不在本轮引入 execute 前的入参强校验（后端 Pydantic 已做边界校验，属增强项，避免扩大改动面）。

### 3.3 离线契约脚本补强（`docs/_verify/output_contract_check.mjs`）

对每个工具新增硬断言：

- `parameters` 必须是对象，且 `parameters.type === "object"`；
- `parameters.properties` 必须是普通对象；
- `parameters.required` 若存在必须是字符串数组，且每个 required 键都在 properties 内；
- 对 parameters 与 output.schema 递归跑官方子集白名单（type 枚举、type/oneOf 互斥、关键字白名单、items/properties 递归）；
- 防止未来再次出现扁平 parameters 漏网。
